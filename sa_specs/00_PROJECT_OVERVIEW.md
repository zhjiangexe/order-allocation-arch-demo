# Archone 系統分析文件

Archone 是物流訂單配貨與履約系統，處理下單、整單配貨、倉內出庫、收貨與取消。

## 1 業務流程

訂單建立後，系統確認所有商品需求均可滿足，才一次預留庫存。倉內完成揀貨、包裝與交運後，系統扣減庫存並完成訂單履約。缺貨時保留需求等待補貨；取消則先確認倉內作業可停止，再取消訂單及釋放預留。

## 3 核心學習重點

### 3-1 系統分析與領域建模

- 將需求轉成業務流程、規則與驗收條件。
- 理解 **Demand and Supply Pattern**：需求、供給、配對與分配。
- 理解 **Ledger Pattern**：異動紀錄、餘額、沖銷與對帳，以及分類帳與複式記帳的差異。
- 劃分 Bounded Context、模組責任與資料所有權。

### 3-2 軟體架構與依賴管理

- 區分 Application、Domain、Infrastructure 的責任。
- 使用 Ports and Adapters 隔離業務規則與技術實作。
- 理解模組化單體與微服務的取捨，以及模組邊界與部署邊界的差異。

### 3-3 庫存、配貨與併發控制

- 理解可用量、預留量與實際扣庫。
- 落實整單配貨、不可超賣等業務不變條件。
- 處理訂單競爭庫存、缺貨等待與重新配貨。

### 3-4 交易邊界與資料一致性

- 定義必須一起成功或失敗的資料更新。
- 區分本地交易的原子性與跨模組的最終一致性。
- 設計業務唯一性、HTTP 重送與冪等回應。
- 理解非同步處理對查詢結果與使用者操作的影響。

### 3-5 事件驅動架構與故障恢復

- 設計事件契約，分離 Application Event 與 Integration Event。
- 理解 Outbox、CDC、Kafka、Inbox 與訊息去重。
- 處理重試、失敗訊息、重送與積壓。
- 透過 catch-up、reconciliation 與排障流程恢復一致性。

### 3-6 長流程編排、取消與補償

- 比較事件協作與 Temporal 流程編排。
- 用狀態機管理跨步驟的等待、推進與失敗。
- 處理取消與出貨的競爭。
- 區分交易回滾與業務補償，理解不可逆操作的限制。

### 3-7 API 契約與資料設計

- 定義請求、回應、驗證規則與錯誤語意。
- 讓 OpenAPI、資料模型與資料字典保持一致。
- 根據存取需求設計資料結構、關聯、約束與索引。

### 3-8 BDD、驗收與設計驗證

- 用 Given／When／Then 描述可觀察的業務行為。
- 涵蓋正常流程、例外、重送與競爭情境。
- 串聯需求、規格案例、自動化測試與 UAT。
- 用測試結果檢驗設計是否符合原本的業務承諾。

各主題皆可進一步討論設計理由、替代方案與適用限制。
